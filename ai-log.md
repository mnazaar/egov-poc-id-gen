# AI log

This service was built with Claude Code (Claude Opus 5.5), driven step by step from an architecture and implementation plan written first. The full step-by-step log, with each prompt, what the AI did and what went wrong, is in **[docs/ai-log.md](docs/ai-log.md)**; decisions made while building are in [docs/NOTES.md](docs/NOTES.md).

**Session transcript:** the exported Claude Code session is in [docs/claude-code-session.txt](docs/claude-code-session.txt), **unedited**. The prompts were typed quickly during the time box, so they are short and contain typos; [docs/prompt-index.md](docs/prompt-index.md) summarises what each one directed, phase by phase, with the line numbers to check against.

## Where the AI was wrong, and how it was caught

1. **A startup-order bug the tests could not see.** Claude assumed that injecting the config loader into the sequence warm-up would load the config first; Quarkus injects a lazy proxy, so in Docker the warm-up ran before the config existed and created no sequences, while all tests passed. It was caught by checking `pg_sequences` on the real 3-instance stack (2 sequences instead of 41) and reading the startup log order, and fixed by calling the loader explicitly.
2. **A JMeter plan that failed every check on good responses.** The request CSV held regexes like `\d{6,}`; the comma split the CSV column, so every ID assertion failed although every response was HTTP 200. The giveaway was "100 % errors" with status 200 in the results file; the CSV is now generated by a script with comma-free patterns and a column-count assertion.
3. **Builds that silently did not rebuild.** Twice, `docker compose build -q` left the old image in place, so a fix appeared not to work. Claude caught it by inspecting the image (its entrypoint, and the old error message still being printed) and switched to normal builds.
4. **Process slips the author caught.** Claude committed a step before the author had reviewed it (because the plan said "commit after each step"), and copied the employer's brief into a folder bound for a public repo. The author stopped the first; Claude reverted both, and `CLAUDE.md` now says nothing is committed before review.
5. **Small errors caught by running things, not by reading them:** an XML comment containing `--` that made JMeter reject its own plan, a form label that broke over three lines (seen in a headless-browser screenshot), and a parallel-test regex that would have counted template names as issued IDs.

## How Claude Code was driven

- **One step per prompt**, each with a done-check from the plan ("render tests pass for all six templates…", "0 duplicates against 3 replicas, and again with a restart mid-run").
- **[`CLAUDE.md`](CLAUDE.md)** gave every session the same rules: follow the plan's API contract exactly, never touch `data/`, never call `nextval` per ID, per-key locks only, and when unsure choose the option that cannot produce a duplicate.
- **Verified on the real stack, not only in tests:** each step was checked through Nginx against 3 replicas, which is where the startup-order bug showed up.
- **The author reviewed every step before commit**, made the judgement calls (Java 25, Nginx over a gateway, no Redis, restart-to-reload), and had them recorded as ADRs.
